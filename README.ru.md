# opencode-log-viewer

[![license: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[English](README.md) | **Русский**

Trace-вьювер для агентов [OpenCode](https://opencode.ai): принимает события от
[opencode-log-plugin](https://www.npmjs.com/package/opencode-log-plugin), хранит их в SQLite и даёт
веб-интерфейс, чтобы по одной конкретной сессии ответить — сколько заняло, куда ушло время, какие
инструменты вызывались и с чем, где агент свернул не туда.

Это инструмент диагностики, а не панель управления агентом. Вьювер никогда не обращается к агенту:
связь только `плагин → вьювер`, по HTTP, в одну сторону.

## Быстрый старт

**1. Запустите вьювер:**

```bash
git clone https://github.com/Mercuron/opencode-log-viewer.git && cd opencode-log-viewer
cp .env.example .env    # обязательно поменять INGEST_SECRET и UI_PASSWORD перед чем-либо ещё
docker compose up -d --build
```

Открыть `http://localhost:8080`. Пусто — это нормально до первого события или до разового импорта
истории («Настройки» → «Импортировать существующие сессии»). Обязательный публичный порт ровно
один — 8080. После `docker compose down && docker compose up` данные сохраняются (именованный том
`viewer-data`).

**2. Подключите к нему агента:** установите [opencode-log-plugin](https://github.com/Mercuron/opencode-log-plugin)
— одна строка в `opencode.json` агента, плюс две переменные окружения, указывающие на этот вьювер:

```env
OPENCODE_LOG_VIEWER_URL=http://<адрес-этого-вьювера>:8080
OPENCODE_LOG_VIEWER_SECRET=<то же значение, что и INGEST_SECRET ниже>
```

## Импорт уже существующей истории

Разовое действие: подтягивает сессии, которые агент накопил до подключения плагина. Дальше новые
сессии появляются сами через плагин — второй раз это делать не нужно (но безопасно: идемпотентно
по `event_id`, повторный запуск не создаёт дублей).

Через UI: «Настройки» → «Импортировать все существующие сессии», указать путь (примонтированный
в контейнер на чтение) и имя источника.

Через CLI в контейнере:

```bash
docker compose exec viewer viewer import --path /import/opencode --source my-agent
```

Поддерживаются обе раскладки хранилища OpenCode, определяются автоматически:
- набор JSON-файлов `storage/session|message|part|todo`;
- SQLite `opencode.db` (раскладка, которую использовало ядро OpenCode на момент написания,
  проверено напрямую по исходникам OpenCode).

Примонтируйте хранилище агента в `docker-compose.yml`:

```yaml
volumes:
  - ${HOME}/.local/share/opencode:/import/opencode:ro
```

## Корреляция с логами инференс-сервера

```bash
docker compose exec viewer viewer import-inference --format llama-server --file /import/llama.log --source my-agent
```

Парсит `prompt eval time` / `eval time` / `n_past` из логов `llama-server` и сопоставляет их с
шагами модели ближайшей по времени сессии источника, по хронологии. Если сопоставить не удалось —
в ленте так и пишется «нет данных инференса», точность не выдумывается.

## CLI

```
viewer import --path <dir|file> --source <name>          # разовый импорт истории
viewer import-inference --format llama-server --file <log> --source <name> [--session-id <id>]
viewer reindex [--session <id>]                           # пересборка индекса из сырых событий
viewer prune                                               # ретеншен немедленно, не дожидаясь суток
```

## Ретеншен

```env
RETENTION_DAYS=90
RETENTION_MAX_GB=20
```

Фоновая задача раз в сутки удаляет самые старые сессии целиком (события + весь производный
индекс) при превышении любого из порогов. Включено по умолчанию и отключается только через
`VIEWER_DISABLE_RETENTION=1` (используется тестами) — отсутствие политики удаления считается
дефектом, а не опцией.

## Безопасность

Два независимых секрета:

```env
INGEST_SECRET=...        # для каждого экземпляра плагина на каждом агент-хосте
UI_PASSWORD=...          # для входа человека в UI
SESSION_COOKIE_KEY=...   # подписывает cookie сессии UI
```

`INGEST_SECRET` не может служить паролем человека: он обязан лежать на каждом хосте с агентом, и
если бы он же был паролем UI, любой, у кого есть доступ к любому агент-хосту, мог бы читать
сессии всех остальных источников — а в сессиях может лежать вывод боевых баз данных.

**Вьювер по замыслу хранит выдержки из боевых логов как есть, без редакции.** Агрессивно вырезать
вывод инструментов при приёме лишило бы инструмент смысла. Редакция — опциональная и применяется
только когда вы явно выбираете «скопировать с цензурой» при экспорте сессии (правила настраиваются
в «Настройках»). Ограничивайте сетевой доступ к вьюверу и **не публикуйте его наружу**.

## Разработка

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
.venv/bin/pytest tests/ -q          # без сети, без запущенного агента — на fixtures
cd frontend && npm install && npm run dev   # проксирует на localhost:8080, см. vite.config.ts
```

Тесты используют `tests/fixtures/` (копия набора fixtures из opencode-log-plugin) — вьювер
разрабатывается и тестируется без живого агента.

## Модель данных и контракт событий

`schema/event.v1.json` — тот же файл, что использует opencode-log-plugin, синхронизируется вручную
— расхождение между ними является поводом для повышения `schema_version`. Полная схема таблиц — в
`migrations/0001_init.sql`.
